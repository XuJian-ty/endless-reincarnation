### 3. 数据与配置层（Game.Data）— 类图要点

### 4. 领域层（Game.Domain）— 类图要点

| 类名 | 职责 | 依赖 |
|------|------|------|
| **Stats** | 11 项基础属性 + 多 StatModifier 叠加，脏标记缓存，暴露 MaxHp/Attack/CritRate 等 | StatModifier（来自武器/Buff/被动） |

### 6. 表现层（Game.Presentation）— 类图要点

| 类名 | 职责 | 依赖 |
|------|------|------|
| **IPlayerContext** | 状态机与各 State 只依赖的接口：Mover/Anim/StateMachine/Transform/PlayerModel、速度与 GetMoveDirection | PlayerController 实现 |
| **PlayerController** | Facade：持有 Mover/Anim/StateMachine/InputHandler，Init、Update 驱动顺序、OnHit/OnPlayerDied、Send Messages 回调入口 | IPlayerContext、PlayerModel、Data |
| **PlayerStateMachine** | Flyweight 状态池、输入→GameAction 映射、策略表（Interrupt/Buffer/Ignore）、单槽预输入、Tick 驱动当前状态 | IPlayerContext、所有 PlayerStateBase |
| **PlayerStateBase** | 抽象基类：Enter/Exit/Tick、GetPolicyFor、AnimNearEnd、CompleteWithPending、GoTo\<T\> | 各具体 State |
| **IdleState / MoveState / …** | 具体状态：OnEnter/OnTick/GetPolicyFor，仅做状态切换决策 | PlayerStateBase、IPlayerContext |
| **PlayerInputHandler** | 每帧构建 PlayerInputData（Move/Look、双击跑、LMB Tap/Hold/SlowTap 标记、技能键等），Init(PlayerInput) | PlayerController、Input System |
| **PlayerMover** | CharacterController 驱动、重力、跳跃、闪避速度、IsNearGround(0.3f)、RotateToward | IPlayerContext |
| **PlayerAnimatorController** | Trigger 与 Float 参数封装、IsCurrentStateNearEnd、GetCurrentNormalizedTime | IPlayerContext |
| **ThirdPersonCamera** | 绕玩家旋转、跟随 | PlayerController 配置 |
| **PlayerInputData** | 单帧输入快照（只读 struct） | PlayerStateMachine、各 State |
| **GameAction** | 枚举：Walk/Run/Jump/NormalAttack/ChargeStart/ChargeRelease/AirAttack/FallAttack/Dodge/Skill | PlayerStateMachine、GetPolicyFor |
| **PendingActionData** | 单槽预输入（Action + SkillIndex） | PlayerStateMachine |
| **TransitionPolicy** | Interrupt / Buffer / Ignore | GetPolicyFor 返回值 |

**状态与动画对应关系（您已确认）**：

- 蓄力：ChargeStartState（对应 Hold 0.2s）→ 动画可包含「开始+循环」；ChargeReleaseState（对应 SlowTap 0.7s）→ 释放动画。代码两个状态，Animator 可设 3 个动画结点（开始、循环、释放），由 Trigger 切换。
- 下落攻击：FallAttackStartState（开始+循环）→ FallAttackLandState（接地动画）。Animator 同样可 3 个结点，由代码在 IsNearGround(0.3f) 时切到 FallAttackLand。
- 着陆：LandState，由 FallState / JumpState 在 IsNearGround(0.3f) 时进入，满足「即将接触地面（0.3m）」的时机。

## 二、写代码流程（建议顺序与原因）

按「先搭骨架再填肉」：先定数据与流程，再做关卡内玩法，最后做 Buff/技能/Boss/完整 UI。

| 阶段 | 做什么 | 原因 |
|------|--------|------|
| **A. 存档与数据结构** | 定义 SaveData/RunData（槽位、关卡、难度、玩家、背包、装备、Checkpoint、LevelSnapshot）；实现 SaveSystem（6 槽、JSON、版本号）。 | 存档结构一定，玩家、背包、关卡都围着它写，避免做到一半大改；退出保存、读档继续都依赖存档。 |
| **B. 玩家模型** | ExpModel（等级、经验、溢出保留）；PlayerModel（Stats+成长+背包+装备+天赋点等）；Inventory（20 格、堆叠规则）；Equipment（当前武器、挂/摘 Modifier）。 | 战斗、掉落、UI 都读「当前血、等级、背包、装备」，收拢到 PlayerModel 后改数值和存档只动这一块。 |
| **C. 游戏流程与主菜单** | GameStateMachine（主菜单/关卡中/暂停）；新游戏/读档/进关卡/暂停/退出保存；主菜单场景 + 新游戏/加载/设置/退出。 | 没有「从菜单进游戏/读档」这条线，Save 和 PlayerModel 用不起来；先打通新游戏→第 1 关、读档→上次关卡。 |
| **D. 关卡内最小可玩** | 角色移动与状态机、简单小怪、CombatCalculator 伤害、经验/金币/掉落、背包拾取、升级与装备。 | 先能「动、打怪、掉东西、升级」，再加技能、Buff、Boss、守卫者，快速形成小循环。 |
| **E. 战斗与状态完善** | 普攻/蓄力/下落攻击/技能状态、预输入与策略表、受击硬直、闪避 60% 提前释放。 | 您当前状态机与预输入已按需求实现，本阶段主要是和伤害、技能、Buff 挂接。 |
| **F. 后续功能** | Buff 3 选 1、技能树与天赋点、守卫者/Boss、宝箱/商店、死亡复活与仙露、Checkpoint 击败 Boss 拷贝与死亡回滚、完整 UI（背包/技能配置/技能树/菜单/战斗回忆）。 | 在 D、E 基础上按需求文档逐个接合，每步都可运行可试玩。 |

**整体思路**：先定「数据怎么存、人怎么成长、怎么进关卡」，再做「在关卡里能动、能打、能掉装」，最后做 Buff/技能/Boss/完整 UI。

## 三、设计模式与架构思路（当前已用）

| 模式/思路 | 使用位置 | 作用 |
|-----------|----------|------|
| **状态模式 + 状态机** | PlayerStateMachine + PlayerStateBase 及所有 *State | 将「当前动作」抽象为状态，切换集中在一处，避免 if-else 面条。 |
| **Flyweight** | PlayerStateMachine 以 Type 为键缓存状态实例 | 同一状态类只建一次，零 GC，ChangeState 时复用。 |
| **策略模式** | GetPolicyFor(GameAction)→Interrupt/Buffer/Ignore | 各状态声明「某输入是打断、缓存还是忽略」，状态机统一执行。 |
| **责任链** | ProcessActions 中按优先级遍历候选动作并查策略 | 先高优先级（闪避/技能/蓄力），再普攻/移动，符合「闪避最高、技能次之」等需求。 |
| **模板方法** | PlayerStateBase 的 Enter/Exit/Tick 调 OnEnter/OnExit/OnTick | 子类只写「进入/退出/每帧」逻辑，生命周期由基类固定。 |
| **Facade** | PlayerController 对外暴露 Init/OnHit/OnPlayerDied，对内编排 Input→StateMachine→Mover | 外部只依赖一个入口，内部顺序与依赖清晰。 |
| **接口隔离** | IPlayerContext 只暴露状态机与 Mover/Anim 等必要能力 | 状态不依赖 PlayerController 具体类，便于测试与替换。 |
| **数据驱动** | WeaponSO/LevelConfigSO/LevelGrowthSO 等 ScriptableObject | 数值与规则由配置决定，改表不改代码。 |
| **DTO 与领域分离** | RunData/PlayerSaveData 与 PlayerModel/Stats 分离，LoadFrom/SaveTo 做转换 | 存档格式稳定，领域模型可独立演进。 |

## 四、注意事项与建议

### 4.1 Unity 配置相关

1. **Input System**
   - 使用 PlayerInput 组件，Behavior = Send Messages。
   - LMB：三个 Action——Tap（≤0.2s 普攻）、Hold（0.2s 蓄力开始）、SlowTap（0.7s 蓄力释放）；其余 Jump/Dodge/Skill/RMB 等按需绑定。
   - PlayerInputHandler.Init(PlayerInput) 在 PlayerController.Init 中调用，保证场景里有 PlayerInput。

2. **Animator**
   - 动作类状态（普攻/蓄力/下落攻击/技能/闪避/受击）建议**不用 Has Exit Time**，全部由代码 Trigger 切换，避免与「连击窗口、60% 提前释放」等逻辑冲突。
   - Idle/Walk/Run 仅由 IdleState、MoveState 触发 Locomotion Trigger；Any State → IdleWalkRun 只认该 Trigger。
   - 蓄力/下落攻击：代码 2 个状态类，Animator 可 3 个动画结点（开始、循环、结束），用 Trigger 或 Bool 在适当时机切换。

3. **着陆时机**
   - 已用 `PlayerMover.IsNearGround(0.3f)`：距地 0.3m 即进 LandState，避免僵硬。

4. **场景与预制体**
   - 主菜单场景：挂 GameEntry，绑 LevelGrowthSO；Canvas 下 MainMenuPanel/SlotSelectPanel/SettingsPanel 按约定命名。
   - 关卡场景：空物体挂 LevelBootstrapper，绑 PlayerController、spawnPoint、LevelConfigSO、DifficultyScalingSO、fallbackLevelGrowth；玩家预制体带 PlayerController、PlayerMover、PlayerAnimatorController、PlayerInputHandler、CharacterController、PlayerInput。

5. **命名空间与 .meta**
   - 改类名/命名空间后，Unity 会通过 .meta 的 GUID 找脚本；若出现 Missing Script，检查是否移动/重命名了脚本导致引用丢失，必要时在 Inspector 重新指定脚本。

### 4.2 存档与 Checkpoint

- **Checkpoint 内容**：只记录「上一关刚击败 Boss 时」的玩家属性、背包、天赋、当前难度、已选 Buff；**不记录当前关新获得的物品**。
- **拷贝时机**：击败当前关 Boss 时，将当前 RunData **深拷贝**一份写入 `run.checkpoint`，再写盘（SaveCurrent）。
- **死亡回滚**：已实现「难度+1、_currentRun=checkpoint、_playerModel.LoadFrom(_currentRun)、SaveCurrent、重新加载当前关卡场景」，保证复活后状态与 checkpoint 一致。

### 4.3 预输入与策略表

- 单槽预输入：**只保留优先级最高的一条**（先遇到的 Buffer 写入，后续同帧 Buffer 不覆盖），避免 Walk 覆盖 NormalAttack 导致连击失效。
- MoveState：Walk/Run 设为 **Ignore**（移动由 OnTick 直接读 input），避免每帧污染 _pending 导致攻击/技能结束后误切回移动。

### 4.4 扩展建议

- **新技能**：加 Skill4State、在 PlayerStateMachine.ExecuteSkill 和输入映射里加分支；技能树数据用 unlockedSkillIds 或独立 SO。
- **新 Buff**：Buff 类型用 string 或 enum，buffIds 存 RunData；进关卡 3 选 1 时从 Buff 池按权重 Roll，选中后加进 buffIds 并给 PlayerModel/Stats 挂 StatModifier 或单独逻辑。
- **新武器品质/属性**：在 WeaponStatRanges 和 WeaponInstance 中加字段，ToModifier 与 Stats 对应；品质开放数量约定在文档/注释中维护即可。

### 4.5 伤害与技能倍率

- 公式已实现：`(攻击×技能倍率)×(0.1+270/(防御+300))×增伤×暴击`，吸血按最终伤害；CombatCalculator 在 Domain 层，技能/普攻调用时传入技能倍率即可。

### 4.6 您文档中的需求对应情况

- **开始界面**：新的游戏/加载存档/声音设置/退出 → MainMenuPanel 已实现；加载存档 3 槽改为 6 槽（SlotCount=6）已与需求一致。
- **声音设置**：Slider+MusicMgr 已实现；按键设置 UI 与键位配置为后续阶段，建议单独一个 KeyBindPanel 与 InputAction 绑定。
- **守卫者数量**：LevelConfigSO.DefaultGuardianCount(1～5)→3,4,6,7,10 已实现。
