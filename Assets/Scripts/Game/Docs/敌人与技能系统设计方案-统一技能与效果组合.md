# 敌人与技能系统设计方案：统一技能 + 效果组合（数据驱动）

**目的**：取消「普攻」与「技能」的区分，全部视为技能；支持多种精英/多种守卫者/Boss 多技能；技能效果（回血、加攻防移速、伤害、击退、位移等）与伤害检测方式（碰撞/范围/射线）均数据配置，新增敌人时**尽量只改数据、不改代码**。

**版本**：1.0  
**日期**：2025-03

---

## 一、需求摘要

| 项目 | 说明 |
|------|------|
| 取消普攻 | 原「普攻」改为技能的一种。近战小怪 = 1 个技能（手持武器近战打击），远程小怪 = 1 个技能（远程射击）。 |
| 敌人种类 | 近战/远程小怪各 1 种；精英怪多种（如 2 种）；守卫者多种（如 3 种）；Boss 5 种。均可后续增加。 |
| 技能数量 | 小怪暂定 1 技能；精英、守卫者、Boss 可多技能，具体个数与释放逻辑由行为树 + 配置决定。 |
| 技能效果 | 回血、加攻击、加防御、加移速、造成伤害、击退、位移（冲刺），或任意组合；每个效果可配置参数。 |
| 伤害检测 | 碰撞检测、范围检测、射线检测，直接内嵌在技能库的伤害效果中配置。 |
| 扩展方式 | 新增敌人 = 加配置项 + 配技能列表 + 配行为树；新增技能 = 加技能配置 + 选效果与检测方式；**目标：不写新 C# 或只实现一次通用效果接口**。 |

---

## 二、整体思路：接口 + 组合 + 数据

- **技能**：一个技能 = 一个配置（SO 或表条目），包含「冷却、伤害检测引用、效果列表」。
- **效果**：每种效果类型对应一个**接口实现**（如 `IEnemySkillEffect.Apply(ctx)`），参数从配置读；一个技能可挂多个效果（回血 + 击退 + 伤害等）。
- **伤害检测**：沿用 `DamageDetectionRunner` 的检测执行器，但检测参数直接写在技能库的伤害效果里，不再额外绑定外部伤害库。
- **敌人**：身份用 **enemyId**（字符串）唯一标识；每种敌人一条**行为配置**（Archetype），里面是「技能槽列表」+ 每个槽对应的技能 ID/引用；行为树里只认「槽位 slot」，不认「近战/远程」。
- **行为树**：意图统一为 **CastSkill(slot)**；条件节点如「CondCanCastSkill(slot)」「CondIsInSkillRange(slot)」，动作节点「ActionSetIntentCastSkill(slot)」；slot 从节点参数（如 `paramInt1`）读，实现完全数据驱动。

这样：
- 增新敌人：在「敌人属性库」与「敌人行为配置库」加一条，给该敌人配 N 个技能槽（引用已有或新建的技能配置），再配行为树（选 slot、顺序、条件）。
- 增新技能：新建一条技能配置，勾选需要的效果类型并填参数，选伤害检测方式（或复用已有 damageName）；行为树里用对应 slot 即可。
- 增新效果类型（极少）：实现一次 `IEnemySkillEffect`，在「效果工厂」里注册；配置里多一种效果类型可选，**无需为每个敌人写代码**。

## 三、敌人身份与配置结构

### 3.1 敌人身份：enemyId 为主，支持多精英/多守卫者/Boss

- **EnemyStatsDatabase（敌人属性库）**：改为按 **enemyId**（string）唯一标识一条。  
  - 示例：`melee_minion`, `ranged_minion`, `elite_1`, `elite_2`, `guardian_1`, `guardian_2`, `guardian_3`, `boss_1`～`boss_5`。  
  - 每条含：enemyId、displayName、baseHp、baseAttack、baseDefense、baseMoveSpeed、gold、exp 等；可保留 **category**（如 Minion/Elite/Guardian/Boss）用于掉落/事件等逻辑。
- **EnemyArchetypeDatabase（敌人行为配置库）**：同样按 **enemyId** 查一条 **EnemyArchetypeSO**（或等价配置）。  
  - 不再用「EnemyType 枚举 5 条」固定；改为列表，每条绑定一个 enemyId，一个 enemyId 对应一种行为配置（感知、巡逻、**技能槽列表**、阶段等）。

这样「2 种精英、3 种守卫者、5 种 Boss」= 在库中加 2+3+5 条 enemyId，无需改枚举。

### 3.2 敌人行为配置（Archetype）中：只保留「技能槽」、不再有「近战/远程」独立开关

- **技能槽列表**：`List<EnemySkillSlotEntry>`，每个元素表示「第 slot 号技能」。
  - `slotIndex`：0～N-1（与行为树 paramInt1 对应）。
  - `skillId` 或 `skillRef`：引用「技能定义」（见下），决定冷却、检测方式、效果。
  - `range`：该技能的施放/判定距离（米），供 CondIsInSkillRange(slot) 用。
  - `phaseMask`（可选）：Boss 阶段 0/1 是否可用（沿用现有 phase0SkillSlots / phase1SkillSlots 思路）。
- 删除：`canMelee`、`canRanged`、`meleeDamageName`、`rangedDamageName`、`meleeRange`、`rangedRange` 等；近战/远程统一为「技能 0」「技能 1」…
- 保留：感知（扇形角度、距离、丢失距离）、巡逻半径、Boss 阶段线（50% 血）等。

## 四、技能定义（数据层）

每个技能一条配置（**EnemySkillSO** 或表条目），字段建议如下。

| 字段 | 说明 |
|------|------|
| skillId | 唯一 ID，Archetype 技能槽引用用。 |
| displayName | 可选，调试/编辑器用。 |
| cooldown | 冷却时间（秒）。 |
| damageEffects | 伤害效果列表；每条直接配置**伤害检测方式**（碰撞/范围/射线）及倍率、命中停顿、命中后子效果等。 |
| effectEntries | **效果列表**：每个元素为「效果类型 + 参数」。 |

**效果类型（枚举 + 参数）**示例：

| 效果类型 | 含义 | 典型参数 |
|----------|------|----------|
| Damage | 造成伤害 | 使用 damageName 的检测与倍率；可选额外倍率。 |
| Heal | 回血 | 数值或基于最大血量比例。 |
| BuffAttack / BuffDefense / BuffMoveSpeed | 加攻/防/移速 | 数值或比例、持续时间。 |
| Knockback | 击退 | 力、时长（可与 Damage 共用配置中的 pushForce/pushDuration）。 |
| Displace | 位移（冲刺） | 距离、方向（朝向目标/前方）、是否可穿人。 |

实现时：每种类型对应一个 **IEnemySkillEffect** 的实现类；配置里只存「类型 + 参数结构」；运行时由**效果工厂**根据类型创建实例，技能执行时对**施放者/目标**调用 `Apply(context)`。这样「一个技能 = 多个效果」完全由数据组合。

## 五、技能效果接口与组合（代码层）

### 5.1 接口

```csharp
// 技能执行时的上下文：施放者、目标（可选）、伤害库、时间等
public interface IEnemySkillEffectContext
{
    EnemyController Caster { get; }
    Transform Target { get; }           // 可选，无目标可为 null
    float DeltaTime { get; }
}

// 单个效果：只做一件事（回血/加 buff/造成伤害/击退/位移）
public interface IEnemySkillEffect
{
    void Apply(IEnemySkillEffectContext ctx);
}
```

### 5.2 效果实现（示例）

- **DamageEffect**：从 ctx 取 damageName，调 `DamageDetectionRunner.TryRunDetection(damageName, caster.transform, ...)`，对命中目标按现有公式扣血并应用击退（若配置有）。
- **HealEffect**：对 caster 或 target 加血，数值从配置读。
- **BuffAttackEffect / BuffDefenseEffect / BuffMoveSpeedEffect**：给 caster（或 target）加临时 buff，持续时间内修改对应属性；需与现有 Buff 系统或临时数值槽对接。
- **KnockbackEffect**：对目标施加力/位移，参数从配置读；可与 Damage 一起用。
- **DisplaceEffect**：移动 caster（或指定对象）一段距离，方向与距离从配置读。

每个效果类**只写一次**；是否启用、数值多少全部在**技能配置的效果列表**里填。

### 5.3 配置与运行时绑定

- 配置中「效果列表」可存为：`List<EnemySkillEffectEntry>`，每项含 `effectType`（枚举）、`paramJson` 或若干 `paramFloat`/`paramInt`。
- 运行时：根据 `effectType` 创建对应 `IEnemySkillEffect`，把参数注入，技能触发时按顺序 `Apply(ctx)`。

这样新增「一种效果」（如眩晕）：只加一个枚举值 + 一个实现类 + 工厂里注册一次；所有技能都可选「眩晕」并配参数，**无需为每个敌人写代码**。

## 六、伤害检测方式（复用现有）

现有检测执行器已支持：

- **RangeOverlap**：球体/扇形/盒体 Overlap，单帧检测。
- **Collision**：帧区间内启用子物体 Collider，由碰撞回调命中。
- **Raycast**：射线/SphereCast。

技能只需在配置里指定伤害效果；该效果内部已包含 detectionType、shape、半径/角度/距离等。  
技能执行时（或动画事件中）调用现有 `DamageDetectionRunner.TryRunDetection(effect, attacker, ...)` 即可，**无需为技能再写一套检测逻辑**。

若某技能「无伤害」（纯回血、纯位移）：damageName 留空，不调伤害检测；只执行效果列表中的 Heal/Displace 等。

## 七、意图与行为树：统一为 CastSkill(slot)

### 7.1 意图

- **删除**：`MeleeAttack`、`RangedAttack`。
- **保留并统一**：`CastSkill`，且带 **SkillSlot**（0～N-1）。
- 其他意图不变：`None`、`Patrol`、`Chase`、`Hurt`。

执行层（EnemyCombat）：只根据 `Intent.Type == CastSkill` 和 `Intent.SkillSlot` 播对应动画（如 Trigger `CastSkill0`～`CastSkillN`），并在动画事件里用该 slot 对应的技能配置的 damageName 做伤害检测与效果应用。

### 7.2 行为树节点（数据驱动）

- **条件**  
  - `CondCanCastSkill(slot)`：从 Archetype 取该 slot 的技能配置，查冷却是否转好、当前阶段是否允许。  
  - `CondIsInSkillRange(slot)`：该 slot 的 range 与当前距离比较。  
  - 保留：CondHasTarget、CondIsHurt 等。
- **动作**  
  - `ActionSetIntentCastSkill(slot)`：写 `CurrentIntent = { Type = CastSkill, SkillSlot = slot }`。  
  - slot 从节点数据 **paramInt1** 读，这样行为树资产里同一节点类型可复用于不同 slot（不同节点 paramInt1 不同）。

删除或弃用：CondCanMelee、CondCanRanged、ActionSetIntentMeleeAttack、ActionSetIntentRangedAttack；近战小怪 = 只有技能 0（近战打击），远程小怪 = 只有技能 0（远程射击），树里用「CondCanCastSkill(0) + CondIsInSkillRange(0) + ActionSetIntentCastSkill(0)」即可。

### 7.3 感知层

- 原 `IsInMeleeRange` / `IsInRangedRange` 改为按 slot 查 Archetype 的「技能槽的 range」：如 `IsInSkillRange(slot)`。
- 或保留通用 `DistanceToPlayer`，条件节点内用 `Archetype.GetSkillRange(slot)` 比较。

## 八、Animator 与动画事件

- 不再区分「近战动画」「远程动画」；统一为「技能 0」「技能 1」… 的动画状态，Trigger 如 `CastSkill0`、`CastSkill1`。
- 动画事件：仍用 `OnDealDamage(damageName)`；damageName 由**该次释放的 slot 对应的技能配置**决定，可在执行层根据当前 Intent.SkillSlot 查 Archetype 得到 damageName 再调 `OnDealDamage(damageName)`，或动画事件里传 slot，由代码查配置取 damageName。

## 九、扩展新敌人 / 新技能的流程（目标：最小改代码）

| 操作 | 在编辑器/数据里做什么 | 是否需要改 C# |
|------|------------------------|----------------|
| 新增一种敌人（如第 3 种精英） | 在敌人属性库加一条 enemyId（如 elite_3）；在行为配置库加一条 Archetype，绑技能槽列表 + 感知/巡逻；可选新建行为树资产或复用已有。 | 否 |
| 给已有敌人多一个技能 | 在 Archetype 的技能槽列表多加一项，引用已有或新建技能配置；行为树里加「CondCanCastSkill(slot) + CondIsInSkillRange(slot) + ActionSetIntentCastSkill(slot)」分支。 | 否 |
| 新增一个技能（新效果组合） | 新建技能配置（SO 或表条目），选伤害检测（或复用 damageName）、填效果列表（类型 + 参数）；动画加状态/事件。 | 否 |
| 新增一种「效果类型」（如眩晕） | 实现一个 `IEnemySkillEffect`，在效果工厂注册；配置里增加该效果类型枚举与参数。 | 是（一次） |

## 十、与现有代码的衔接要点

- **EnemyController**：仍持有一个 Archetype（按 enemyId 从库取）；Archetype 结构改为「仅技能槽列表 + 每槽 range/phase」，不再有 canMelee/canRanged/meleeRange 等。
- **EnemyCombat**：只处理 `CastSkill`，根据 `SkillSlot` 设 Animator Trigger（CastSkill0～N）；`OnDealDamage` 可由调用方传入 damageName，或根据当前正在播放的 slot 从 Archetype 取 damageName。
- **EnemyPerception**：提供 `IsInSkillRange(slot)` 或 `GetSkillRange(slot)`，供行为树条件用。
- **EnemyAI / 行为树**：用 CondCanCastSkill、CondIsInSkillRange、ActionSetIntentCastSkill + paramInt1；从 Archetype 取技能列表与冷却/阶段。
- **冷却**：每个技能槽在 EnemyController 或专门组件中维护「上次释放时间」；CondCanCastSkill(slot) 查当前时间 - lastCastTime >= cooldown。
- **EnemyStatsDatabase / EnemyArchetypeDatabase**：改为按 enemyId 的列表/字典查找，支持任意数量精英/守卫者/Boss。

## 十一、实现顺序建议

1. **数据与配置**：定义 EnemySkillSO（或等效）、效果条目结构、Archetype 改为技能槽列表；EnemyStats + Archetype 库改为 enemyId 驱动。
2. **效果接口与实现**：IEnemySkillEffect、上下文、Damage/Heal/Knockback/Displace/Buff 等实现，效果工厂。
3. **意图与执行**：意图去掉 MeleeAttack/RangedAttack，统一 CastSkill(slot)；EnemyCombat、EnemyPerception 适配；冷却与阶段逻辑。
4. **行为树**：CondCanCastSkill(slot)、CondIsInSkillRange(slot)、ActionSetIntentCastSkill(slot)，Builder 与 FromDataBuilder 支持 paramInt1 作为 slot；默认树与资产改为「技能槽」逻辑。
5. **一键创建与默认数据**：默认近战小怪/远程小怪各 1 技能，精英 2 种、守卫者 3 种、Boss 5 种，每类若干技能；行为树资产更新。
6. **文档与说明书**：更新敌人 AI 设置说明书、设计说明与实现计划，指向本方案。

按上述顺序可实现「只改数据扩展敌人与技能、效果用接口组合」的目标；后续新增敌人或技能只需配数据和行为树即可。
