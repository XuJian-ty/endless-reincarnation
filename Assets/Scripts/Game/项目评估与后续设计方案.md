## 二、结构与架构评价

### 2.1 分层与依赖

- **优点**：README_Architecture 与类图文档定义清晰，UI → 表现 → 流程 → 领域 → 数据 → 基础设施，依赖单向，无循环；数据驱动（SO + DTO）与运行时分离明确。
- **商业级**：✅ 达到；分层边界清楚，便于多人协作与单测。

### 2.2 设计模式使用

- **状态机 + Flyweight**：PlayerStateMachine 以 Type 缓存状态，零 GC，策略表（Interrupt/Buffer/Ignore）集中管理，符合商业项目对可维护性与性能的要求。
- **Facade + 接口隔离**：PlayerController 对外 Init/OnHit/OnPlayerDied，对内 IPlayerContext 只暴露 Mover/Anim/StateMachine 等必要能力，状态不依赖具体 Controller。
- **组合优于继承**：PlayerModel = Stats + ExpModel + Inventory + Equipment，扩展 Buff/Skill 时只需加组件，不必改继承树。
- **商业级**：✅ 达到；模式使用得当，扩展点明确。

### 2.3 数据与配置

- **优点**：SO 只做定义，运行时用 RunData/WeaponInstance/LevelSnapshot；存档版本号、Checkpoint 深拷贝、LevelSnapshot 支持读档继续，结构完整。
- **不足**：Buff、技能树、关卡内实体（怪物/宝箱/商店）的运行时数据结构尚未与 RunData/LevelSnapshot 完全对接（如 EnemySnapshot 已定义但无生成与恢复逻辑）。
- **商业级**：✅ 数据结构达标；⚠️ 需在后续阶段把 Buff/Skill/关卡实体与存档和流程接好。

## 三、各模块多维度评价

### 3.1 表现层（玩家输入与动作）

| 维度 | 评价 | 说明 |
|------|------|------|
| **功能完整性** | ✅ 商业级 | 移动/跳跃/闪避/普攻连击/蓄力/空中普攻/下落攻击/4 技能/受击，与需求文档一致 |
| **可维护性** | ✅ 商业级 | 状态按职责拆分，GetPolicyFor 表驱动，新增动作只需加状态类与策略 |
| **性能** | ✅ 商业级 | Flyweight 状态复用、单槽预输入、脏标记 Stats 缓存，无多余 GC |
| **可测试性** | ⚠️ 良好 | IPlayerContext 可 Mock，但状态与 Animator/Mover 耦合，纯逻辑单测需封装 |
| **已知问题** | 键盘松键延迟 | 已确认为系统/键盘上报问题，非代码缺陷；可文档说明或提供「鼠标前进」等备选 |

**优化建议**  
1. **可选**：将「当前状态名」或「当前动作 ID」通过 IPlayerContext 暴露给 HUD/调试，便于 UI 与排查。  
2. **可选**：为关键状态（如 HitStun、Dodge）提供「剩余时间/进度」查询接口，便于 UI 显示无敌条、硬直条等。

### 3.2 领域层（Stats、PlayerModel、战斗公式）

| 维度 | 评价 | 说明 |
|------|------|------|
| **功能完整性** | ✅ 商业级 | Stats+Modifier、CombatCalculator、ExpModel、Inventory、Equipment、PlayerModel 与存档互转完整 |
| **数值安全** | ✅ 商业级 | 伤害公式有 Max(0,…)、Clamp01 等防护，暴击用 RNG 注入，便于测试 |
| **扩展性** | ✅ 商业级 | 新属性加 StatModifier 与 Stats 缓存项即可；Buff/被动后续挂 Modifier |

**优化建议**

2. **PlayerModel**：BuffIds/UnlockedSkillIds 目前为 List，若需频繁查找，可增加 `HashSet` 或封装「Contains」方法，避免线性查找。

## 四、整体不足与优化方案汇总

| 类别 | 问题 | 优化方案 |
|------|------|----------|
| **架构** | 关卡内逻辑（刷怪、Boss、宝箱）尚未模块化 | 引入 LevelDirector 或 LevelStateMachine，按「守卫者存活数、Boss 是否已召唤」驱动阶段；刷怪/掉落用配置 + 事件 |
| **数据** | Buff、技能树、商店等配置与运行时未接 | 补 BuffSO、SkillSO、ShopItemSO；PlayerModel 或单独 BuffContainer 持有效果列表，技能树用 UnlockedSkillIds + 前置依赖表 |
| **流程** | 击败 Boss 后 checkpoint 写入与选关 UI 未实现 | 在关卡内发出 OnBossDefeated；GameStateMachine 或 LevelDirector 订阅后写 checkpoint、SaveCurrent、弹「本关再玩/下一关」面板 |
| **表现** | 无怪物、无伤害来源与受击反馈闭环 | 实现简单 EnemyController（血量、受击、死亡事件）；PlayerController.OnHit 已存在，由怪物/陷阱调用并传入 CombatCalculator 结果 |
| **UI** | 缺 HUD、背包、技能、商店、Buff 选择、战斗回忆 | 按「后续设计方案」分阶段实现，优先 HUD 与 Buff 选择（进关卡必现） |
| **测试** | 领域层与流程层单测不足 | CombatCalculator、ExpModel、InventoryModel 等纯 C# 类可先写单元测试；存档用 JSON 往返 + 关键字段断言 |

## 五、后续设计方案（按阶段）

### 阶段 1：关卡内最小可玩（优先）

**目标**：能在关卡里移动、打怪、掉经验/金币、升级；无 Buff/技能树/商店，仅验证战斗与成长闭环。

| 序号 | 内容 | 设计要点 |
|------|------|----------|
| 1.1 | **简单怪物** | 新建 EnemyController（或 EnemyView），持 EnemyStatsSO、当前血量；受击时调用 CombatCalculator（玩家 Stats、技能倍率、怪物防御），扣血；死亡时发 EventCenter("EnemyDied", enemyData)，带位置/类型/掉落权重。 |
| 1.2 | **伤害与受击闭环** | 玩家普攻/技能命中时，由表现层（射线或动画事件）检测目标，调用 CombatCalculator.CalculateDamage(PlayerModel.Stats, ...)，对目标扣血、玩家吸血回血；怪物攻击玩家时调用 PlayerController.OnHit(damage, stunDuration)，内部扣 CurrentHp、ChangeState<HitStunState> 或触发死亡。 |
| 1.3 | **经验与金币** | 怪物死亡时根据配置给经验、金币；调用 PlayerModel.AddExp、Gold += 量；升级时 LevelGrowthSO.GetStatsForLevel 更新 Stats，CurrentHp/CurrentMp 可按比例或满血蓝处理（与需求一致即可）。 |
| 1.4 | **简单掉落** | 精英怪死亡按 DropTableSO Roll，生成 WeaponInstance 或药剂实例；先在地面生成可拾取物体（或占位），玩家碰撞时若背包未满则 Inventory.Add，并销毁掉落物。 |
| 1.5 | **关卡生成占位** | 用 LevelConfigSO 决定本关「怪物数量上限、精英比例」等；LevelBootstrapper 或新类 LevelSpawner 在 Start 时按配置在指定区域（如随机点）生成若干 EnemyController；难度用 DifficultyScalingSO 放大怪物血量/攻击。 |

**交付物**：关卡内可移动、普攻/技能打怪、怪物死亡掉经验金币、玩家升级、简单掉落进背包（背包逻辑已有，只需拾取入口）。

---

### 阶段 2：Buff 与进关卡流程

**目标**：进入关卡时弹出 Buff 3 选 1，选中后写入 RunData.buffIds，并对 PlayerModel.Stats 生效。

| 序号 | 内容 | 设计要点 |
|------|------|----------|
| 2.1 | **BuffSO** | 新建 ScriptableObject：buffId、显示名、描述、对应 StatModifier 或效果类型（如增伤 30%）；可做 13 种 Buff 配置。 |
| 2.2 | **Buff 选择面板** | UI：显示 3 个随机 Buff（从池中 Roll，可重复），玩家选一；确认后 PlayerModel 应用该 Buff（加 Modifier 或写 buffIds 再由 PlayerModel 从 BuffSO 表解析并挂 Modifier）。 |
| 2.3 | **进关卡时机** | LevelBootstrapper 在 Start 中，若 run.levelSnapshot == null（全新进关），先 ShowPanel<BuffSelectPanel>，传入本次 3 个 Buff 选项；玩家选择并关闭面板后再执行当前「放置玩家、TODO 移除」等逻辑。 |

**交付物**：新游戏/死亡复活进关时弹出 Buff 3 选 1，选中后生效并进入关卡。

---

### 阶段 3：守卫者与 Boss

**目标**：每关固定数量守卫者，全部击杀后 5 秒召唤 Boss；Boss 击杀后写 checkpoint、弹本关/下一关。

| 序号 | 内容 | 设计要点 |
|------|------|----------|
| 3.1 | **守卫者** | 用 LevelConfigSO 取本关守卫者数量（3/4/6/7/10）；生成时标记为守卫者类型；死亡时 EventCenter("GuardianDied")，BossProgressService 或 LevelDirector 计数。 |
| 3.2 | **Boss 降临** | 当守卫者全部死亡，计时 5 秒后 EventCenter("BossSpawnRequest")；LevelDirector 在玩家附近随机位置生成 Boss（从「未击败 Boss 池」随机选）；Boss 死亡发 OnBossDefeated。 |
| 3.3 | **击败 Boss 后** | 订阅 OnBossDefeated：将当前 RunData 深拷贝到 run.checkpoint；defeatedBossIds.Add(bossId)；SaveCurrent；ShowPanel<BossClearPanel>（本关再玩 / 下一关）；选「下一关」则 levelIndex++，LoadScene 下一关。 |
| 3.4 | **天赋点** | 守卫者死亡时 PlayerModel.TalentPoints += 1；Boss 不掉落天赋点（需求已定）。 |

**交付物**：守卫者全灭 → 5 秒后 Boss 降临 → 击败后 checkpoint 写入、选关面板、可进下一关。

---

### 阶段 4：技能树与技能配置

**目标**：12 被动 + 4 主动，技能树解锁、主动技能耗蓝与键位配置。

| 序号 | 内容 | 设计要点 |
|------|------|----------|
| 4.1 | **SkillSO** | 每个技能一条：id、被动/主动、消耗天赋点、前置技能 id、效果（如加某 StatModifier）；主动技能额外：耗蓝、技能倍率、动画或表现参数。 |
| 4.2 | **技能树逻辑** | PlayerModel.UnlockedSkillIds 已存在；解锁时校验前置是否在 UnlockedSkillIds 中、TalentPoints 是否足够；解锁后加入 UnlockedSkillIds，被动效果挂到 Stats。 |
| 4.3 | **主动技能耗蓝** | 技能状态 OnEnter 时若 !PlayerModel.CanSpendMp(cost) 则直接回 Idle/Fall；否则 SpendMp 再播动画。 |
| 4.4 | **技能配置面板** | 可选：键位与技能槽绑定（如 Q→Skill0），存到 RunData 或单独配置；技能配置面板显示 4 个主动技能与当前键位，支持修改。 |

**交付物**：天赋点解锁技能树、主动技能耗蓝、可选键位配置。

---

### 阶段 5：商店、宝箱与完整 UI

**目标**：商店/宝箱交互、HUD、背包面板、技能树面板、战斗回忆等。

| 序号 | 内容 | 设计要点 |
|------|------|----------|
| 5.1 | **商店** | 每关 1～2 商店，靠近可交互；ShowPanel<ShopPanel>，5 个槽位按 DropTableSO 权重 Roll 物品与价格；购买时扣 Gold、Inventory.Add。 |
| 5.2 | **宝箱** | 按 LevelConfigSO 生成宝箱位置与数量；开启时播放动画、按表 Roll 掉落物生成地面拾取物；LevelSnapshot.openedChestIds 记录已开宝箱，读档时不重复生成。 |
| 5.3 | **HUD** | 血条/蓝条/等级/金币，数据源 PlayerModel；可用 EventCenter 订阅血量变化等刷新。 |
| 5.4 | **背包/装备 UI** | 列表绑定 InventoryModel、当前装备槽；装备/卸下调用 EquipmentModel，刷新 UI。 |
| 5.5 | **战斗回忆** | 主菜单在 isGameCleared 时显示入口；进入后显示已击败 Boss 列表，选择其一再 LoadScene 到对应 Boss 场景或复用关卡场景并只生成该 Boss，无奖励。 |

**交付物**：关卡内商店/宝箱可玩，主菜单与关卡内主要 UI 齐全。

### 阶段 6：死亡与仙露、Checkpoint 细化

**目标**：死亡时可选仙露复活；Checkpoint 与「当前关新获得物品」的边界与需求一致。

| 序号 | 内容 | 设计要点 |
|------|------|----------|
| 6.1 | **死亡面板** | 玩家死亡时先 ShowPanel<DeathPanel>：显示「复活（消耗仙露）」与「放弃（回滚 Checkpoint）」；选复活则扣仙露、难度+1、当前关物品归还（按需求）、重新进关并弹 Buff 选择。 |
| 6.2 | **仙露** | 背包或 PlayerModel 中记录仙露数量；复活时扣除，不足则灰掉「复活」按钮。 |
| 6.3 | **Checkpoint 内容** | 确保 checkpoint 存的是「上一关 Boss 击败后」的完整 RunData（含背包、装备、Buff、天赋点等）；当前关新获得的物品不写入 checkpoint，死亡回滚后只保留 checkpoint 内数据。 |

**交付物**：死亡流程与需求一致，仙露复活可选。
