# 菜单面板与按键配置面板：编辑器里一步一步怎么做

依据**功能需求说明书**：**十九、菜单与暂停**、**十三、按键配置**。

- 按 **Esc** 打开**菜单面板**（游戏暂停）；按 **X** 打开**按键配置面板**。
- 二者与背包、技能树一样，由 **UIManager** 加载、挂在**同一 Canvas** 下，菜单在 **Top** 层，按键配置在 **Mid** 层。

---

## 挂载建议（Esc/X/C/V 只在这 5 个关卡场景生效）

依据需求书**十九、菜单与暂停**与**四、关卡与地图**：菜单、按键配置、背包、技能树**仅在关卡内**可用（主菜单没有这些面板）。游戏共**五关**，每关独立场景；主菜单是单独场景且**没有玩家**。

**推荐：挂在玩家身上**

- 在** 5 个关卡场景**里，**玩家物体**上挂 **GameplayInputEvents** 和 **GameplayUIInputBridge**，并把 **PlayerInputActions** 拖到 GameplayInputEvents 的 **Input Action Asset**。
- 主菜单场景**没有玩家**，自然不会带有这两个组件，Esc/X/C/V 在主菜单不会触发任何面板，**天然满足「只在这 5 个游戏场景可打开」**。
- 优点：不用额外空物体；玩家在哪个场景，按键就在哪个场景生效；和 PlayerInput 一起都挂在玩家上，维护简单。

**备选：挂在关卡场景的独立物体上**

- 在 5 个关卡场景里各建一个空物体（如 **GameplayInput**），挂 **GameplayInputEvents**（拖入 PlayerInputActions）和 **GameplayUIInputBridge**；**主菜单场景不放**该物体。
- 优点：输入逻辑与玩家解耦；若以后有「关卡内无玩家也能开菜单」等需求，仍可响应。缺点：需在 5 个关卡场景里各放一次并记得拖 Asset。

**结论**：两种方式都能做到「这几个面板只在 5 个游戏场景可打开」。若没有特殊解耦需求，**建议直接挂在玩家身上**。

---

## Unity 编辑器里应该做什么（按顺序做）

下面是一份**纯操作清单**：在 Unity 里按顺序做即可，每一步都可以直接照着点。

---

### 步骤 0：前提检查（先做一次）

1. **Canvas 和 EventSystem 能被打包加载**
   - 打开 **Project** 窗口，确认 **Resources** 下有 **UI** 文件夹（没有就：在 Resources 上 **右键 → Create → Folder**，命名为 **UI**）。
   - 确认 **Resources/UI/** 下有 **Canvas** 和 **EventSystem** 两个预制体（若你在别处如 Prefabs/UI 有，就**复制**一份到 **Resources/UI/**，这样 UIManager 的 `Load("UI/Canvas")` 才能找到）。
2. **Canvas 结构**
   - 在 Project 里**双击**打开 **Resources/UI/Canvas** 预制体（或拖到 Hierarchy 看一眼）。
   - 选中 Canvas 根节点，看 **Inspector** 下是否有四个子物体：**Bot、Mid、Top、System**。没有的话在 Canvas 下 **右键 → Create Empty** 四次，分别命名为 **Bot**、**Mid**、**Top**、**System**，保存预制体。
3. **关卡场景里的「输入 + UI 桥接」**
   - **PlayerInputActions** 可以只挂在玩家身上，但按 Esc/X/C/V **弹面板**靠的是 **GameplayInputEvents + GameplayUIInputBridge**，不是 PlayerInput。所以场景里必须有物体挂这两个组件，并把 **PlayerInputActions** 拖到 **GameplayInputEvents** 的 **Input Action Asset**。
   - **做法一（推荐）**：选中**玩家物体**，**Add Component** 添加 **Gameplay Input Events**，在 **Input Action Asset** 里拖入 **PlayerInputActions**（与 PlayerInput 用同一份）；再 **Add Component** 添加 **Gameplay UI Input Bridge** 和 **Cursor Visibility Controller**。这样仍是「只挂玩家身上」。
   - **做法二**：**右键 → Create Empty** 命名为 **GameplayInput**，挂 **Gameplay Input Events**（拖入 PlayerInputActions）、**Gameplay UI Input Bridge** 和 **Cursor Visibility Controller**。
   - **重要**：**只选一种做法**，只在一个物体上挂这三个组件。不要同时在玩家和 GameplayInput 上都挂，否则会出“按 X 关不掉、开面板还能移动”等问题。
   - 若 C/X/V/Esc 绑在 **UI** 地图里，代码会先在 Gameplay、再在 UI 里找。**Z 键**已在 **PlayerInputActions** 的 **Gameplay** 与 **UI** 地图中作为 **ToggleCursor** 添加，无需在编辑器里新建；若要改键，可在 **Assets/Input/PlayerInputActions** 里编辑对应地图下的 ToggleCursor 绑定。**Ctrl+S** 保存场景。

### 步骤 1：菜单面板（MenuPanel）

1. **在场景里做出菜单**
   - 在 **Hierarchy** 里找到 **Canvas**（若场景里没有 Canvas，从 Project 把 **Resources/UI/Canvas** 拖进 Hierarchy）。
   - 展开 Canvas，在 **Top** 上 **右键 → Create Empty**，命名为 **MenuPanel**。
   - 选中 **MenuPanel**，在 Inspector 点 **Add Component**，搜索 **Menu Panel**，添加 **Menu Panel (Script)**。
   - 选中 MenuPanel，在 **Rect Transform** 里把 **Anchor** 设为拉伸全屏（点击左上角方框选 bottom-right 的 stretch-stretch），**Left/Right/Top/Bottom** 都设为 0（或你喜欢的尺寸）。
2. **背景**
   - 选中 **MenuPanel**，**右键 → UI → Image**，命名 **Bg**；在 Bg 的 Rect Transform 里锚点选 stretch-stretch，Left/Right/Top/Bottom 设 0；在 **Image** 组件里 **Color** 调成半透明黑（Alpha 约 180）。
3. **内容区**
   - 在 **MenuPanel** 下 **右键 → Create Empty**，命名 **Content**。选中 Content，Rect Transform 里 **Anchor** 选中间（Middle-Center），**Width** 约 320，**Height** 约 360，**Pos X/Y** 为 0。**Add Component → Image**，Color 选一个深色当底板。
4. **四个按钮**
   - 选中 **Content**，**右键 → UI → Button - TextMeshPro**（或 **Button**），Unity 会生成一个 Button，把它**重命名**为 **Btn_Resume**；选中其子物体 **Text (TMP)** 或 **Text**，把文字改成 **继续游戏**。
   - 再在 Content 下 **右键 → UI → Button** 三次，分别重命名为 **Btn_Quit**、**Btn_Settings**、**Btn_BattleMemory**，文字分别改为 **退出游戏**、**声音设置**、**战斗回忆**。
   - 选中 **Content**，**Add Component → Vertical Layout Group**，Spacing 设 10，这样四个按钮会竖排。**不要**给这四个按钮在 Inspector 里挂 **On Click ()**，脚本会按名字自动处理。
5. **可选：标题**
   - 在 Content 下 **右键 → UI → Text**，命名 **Title**，内容写「菜单」或「暂停」，拖到最上方。
6. **做成预制体**
   - 在 **Project** 里确认有 **Resources/UI**。
   - 在 **Hierarchy** 里选中 **MenuPanel**（整棵，包含 Bg、Content、所有按钮），**拖到 Project 的 Resources/UI 文件夹**里，松开后生成预制体；若名字不是 **MenuPanel**，在 Project 里**重命名**为 **MenuPanel**。
   - 回到 Hierarchy，**删掉**场景里刚才那棵 MenuPanel（运行时会由 UIManager 从预制体加载）。

### 步骤 2：按键配置面板（KeyConfigPanel）

1. **面板根节点**
   - 在 **Canvas** 下选中 **Mid**，**右键 → Create Empty**，命名为 **KeyConfigPanel**。
   - 选中 KeyConfigPanel，**Add Component** 搜索 **Key Config Panel**，添加 **Key Config Panel (Script)**。
   - Rect Transform：Anchor 可设为 stretch 或居中，例如 Width 500、Height 400。
2. **背景 Bg**
   - 在 **KeyConfigPanel** 下 **右键 → UI → Image**，命名 **Bg**，铺满父物体（Anchor stretch，四边 0），Color 半透明黑或深色。
3. **标题**
   - 在 **KeyConfigPanel** 下 **右键 → UI → Text**，命名 **Title**，内容「按键配置」，拖到面板顶部。
4. **关闭按钮**
   - 在 **Bg** 下 **右键 → UI → Button**（这样关闭按钮会跟着背景右上角），命名 **Btn_Close**，按钮文字改为「关闭」。在 Bg 的 Rect Transform 里把 Btn_Close 拖到右上角（或你习惯的位置）。
5. **Scroll View（带 KeyList）**
   - 在 **KeyConfigPanel** 下 **右键 → UI → Scroll View**。会生成 **Scroll View**，下面有 **Viewport** 和 **Content**。
   - 选中 **Content**，在 Hierarchy 里**右键 Content → Rename**，改名为 **KeyList**（或删掉 Content，在 Viewport 下 **Create Empty** 命名 **KeyList**，然后选中 Scroll View 根，在 **Scroll Rect** 组件里把 **Content** 引用拖成 KeyList）。
   - 选中 **KeyList**：
     - **Add Component → Vertical Layout Group**：Spacing 设 6，**Child Force Expand** 只勾 **Width**，**Child Control Size** 勾 **Height**。
     - **Add Component → Content Size Fitter**：**Vertical Fit** 选 **Preferred Size**。
   - 选中 **KeyConfigPanel**（根），在 Inspector 的 **Key Config Panel (Script)** 里：
     - **Input Action Asset** 从 Project 把 **Assets/Input/PlayerInputActions** 拖进去。
     - **Key List Root** 把 Hierarchy 里的 **KeyList** 节点拖进去。
6. **在 KeyList 下手动创建 16 行（顺序不能错）**
   - **做第 1 行**：在 **KeyList** 下 **右键 → Create Empty**，命名如 **技能1** 或 **Row0**。选中它，**Add Component** 搜索 **Key Config Row**，挂上。在该物体下：**右键 → UI → Text** 命名 **Label**；再 **UI → Text** 命名 **KeyText**；**UI → Button** 命名 **Btn_Rebind**，文字改「重绑」；再 **UI → Button** 命名 **Btn_Reset**，文字改「恢复默认」。选中该行根物体，在 **Key Config Row** 上把 **Label**、**Key Text**、**Rebind Button**、**Reset Button** 四个引用拖好。
   - **做第 2～16 行**：选中第 1 行根物体，**Ctrl+D** 复制 15 次，得到共 16 行。在 **Hierarchy** 里**拖拽调整 KeyList 下 16 个子物体的上下顺序**，使顺序为：技能1、技能2、技能3、技能4、回血药剂、回蓝药剂、按键配置、背包、技能树、菜单、闪避、跳跃、移动-上、移动-下、移动-左、移动-右（与文档「七、16 行顺序」表一致）。
   - 脚本按 KeyList 的 **GetChild(0)～GetChild(15)** 依次绑定，顺序错了键位会对错。
7. **做成预制体**
   - 在 **Hierarchy** 里选中 **KeyConfigPanel**（整棵），拖到 **Project 的 Resources/UI/** 下，重命名为 **KeyConfigPanel**（必须这个名字）。
   - 删掉场景里这棵 KeyConfigPanel。

### 步骤 3：再检查场景与测试

1. **场景里要有**
   - **Canvas** 会在 UIManager 第一次被用时从 Resources/UI/Canvas 加载，所以关卡场景里**可以没有** Canvas（若你希望先看到 UI，可拖一个 Canvas 进场景用于编辑，运行时会用 UIManager 加载的那份）。
   - **GameplayInput**（或你起的名字）上必须有 **GameplayInputEvents**（已绑 PlayerInputActions）和 **GameplayUIInputBridge**。
2. **运行测试**
   - 运行关卡场景，按 **Esc**：应弹出菜单（继续游戏 / 退出游戏 / 声音设置 / 战斗回忆），点「继续游戏」关闭。

## 一、菜单面板（MenuPanel）配置

**需求十九**：玩家在关卡内按 Esc 打开**菜单面板**，此时**游戏暂停**（时间停止）。菜单内可选：

- **继续游戏**（关闭菜单并恢复）
- **退出游戏**（保存并返回主菜单）
- **声音设置**（仅关卡内背景音乐滑块，按当前存档独立保存，见《声音设置面板编辑器操作说明》）
- **战斗回忆**（仅当游戏通关即打败完所有 Boss 后显示）

### 1.1 在场景里搭菜单面板结构

1. **建菜单根节点**
   - 在 **Hierarchy** 里找到 **Canvas**（若没有，从 Project 拖入 **Resources/UI/Canvas**）。
   - 在 **Canvas** 的 **Top** 子物体下 **右键 → Create Empty**，命名为 **MenuPanel**。
   - 选中 **MenuPanel**，**Add Component** 搜索 **Menu Panel**（`Game.UI.MenuPanel`），挂上。
   - **RectTransform**：锚点建议 **Stretch-Stretch**，Left/Right/Top/Bottom 都 0，铺满屏幕；或居中、固定宽高（如 400×500），随你风格。

2. **做半透明背景（可选）**
   - 在 **MenuPanel** 下 **右键 → UI → Image**，命名如 **Bg**。
   - 锚点 Stretch-Stretch，四边 0；**Color** 半透明黑（如 A 约 180），背后游戏画面会变暗。

3. **做居中内容区（推荐）**
   - 在 **MenuPanel** 下 **右键 → Create Empty**，命名如 **Content**。
   - **Content** 的 RectTransform：锚点 **Middle-Center**，宽约 320，高约 360；Pos X/Y 为 0。
   - 在 **Content** 上 **Add Component → Image** 当底板，Color 不透明深色即可。

4. **做按钮（名字必须和下面一致）**
   - 在 **Content** 下建四个 Button（**Button - TextMeshPro** 或 **Button** Legacy）：
     - **Btn_Resume**，文字「**继续游戏**」
     - **Btn_Quit**，文字「**退出游戏**」（需求：保存并返回主菜单）
     - **Btn_Settings**，文字「**声音设置**」
     - **Btn_BattleMemory**，文字「**战斗回忆**」
   - **Btn_BattleMemory** 会由脚本在每次打开菜单时根据是否通关（`CurrentRun.isGameCleared`）自动显示/隐藏，你只需做好按钮并命名正确即可。
   - 排布：用 **Vertical Layout Group** 挂在 Content 上（Spacing 约 10），或手动上下排好。**不要**在 Inspector 里给按钮手动挂 OnClick：**BasePanel** 按名字自动注册，**MenuPanel** 已重写 **OnClick**。

5. **按钮与逻辑对应（脚本已实现，对齐需求十九）**
   - **Btn_Resume** 或 **Btn_Close**：关闭菜单并恢复游戏（Resume + HidePanel）。
   - **Btn_Quit**：**保存并返回主菜单**（SaveAndQuit），不是退出应用。
   - **Btn_Settings**：打开**关卡内声音设置**面板（LevelSoundPanel，仅关卡内 BGM 滑块，按当前存档保存）。
   - **Btn_BattleMemory**：打开战斗回忆面板（仅通关后该按钮会显示；需求：选择要重新挑战的 Boss）。

6. **可选：标题**
   - 在 **Content** 下 **右键 → UI → Text**，命名如 **Title**，内容「菜单」或「暂停」。脚本不强制要求。

### 1.2 做成预制体并放到 Resources/UI/

1. 在 **Project** 里确认有 **Resources/UI**（没有则在 Resources 下建 **UI**）。
2. 在 **Hierarchy** 里选中 **MenuPanel**（整棵，含 Bg、Content、所有按钮），**拖到 Project 的 Resources/UI/** 下，生成预制体 **MenuPanel**。
3. **预制体名必须为 MenuPanel**，UIManager 按 `"MenuPanel"` 加载，即 **Resources/UI/MenuPanel**。
4. 场景里这棵 MenuPanel 可以**删掉**，运行时会由 UIManager 从预制体实例化到 Canvas/Top 下。

### 1.3 测试

- 运行关卡，按 **Esc**，菜单出现在 **Top** 层，游戏暂停。
- 点「继续游戏」→ 关闭菜单并恢复。
- 点「退出游戏」→ 保存并切回主菜单场景（不退出应用）。
- 点「声音设置」→ 弹出 **LevelSoundPanel**（仅关卡内 BGM 滑块，调节后按当前存档保存）。
- 通关后再次打开菜单，「战斗回忆」按钮应出现；未通关时该按钮会被隐藏。

## 二、按键配置面板（KeyConfigPanel）配置

**需求十三**：玩家在游戏中可打开**按键配置面板**，**为已解锁的主动技能、药剂及其他操作直接配置按键**，无需选择佩戴；未配置前使用默认键位（如 技能对应 Q、E、R、F，药剂对应 T、Y 等）。

**需求十九**：按键配置面板 X 键打开，可配置**技能、药剂、普攻、蓄力、闪避、跳跃、移动**等游戏内所有操作的按键。

### 2.0 改键实现思路（实现方式说明）

下面说明「改按键」是用**哪种方式**实现的，方便你理解和扩展。

---

**一、整体方式：Unity 新输入系统的「绑定覆盖」+「交互式重绑定」**

- 项目用的是 **Unity Input System**（新输入系统），所有按键都定义在 **PlayerInputActions** 这份 **InputActionAsset** 里（例如 Gameplay 下的 Move、Jump、Skill0～3、ToggleBackpack 等）。
- 改键**不修改** .inputactions 资源文件本身，而是在**运行时**对某个 Action 的某个 **Binding** 施加 **Override（覆盖）**：覆盖掉编辑器里设的默认键，换成玩家刚按下的键。
- 覆盖是**内存里**的，关游戏就没了，所以要**持久化**：把当前所有「有覆盖」的 (Action, Binding 下标, 新路径) 存到 **PlayerPrefs**；下次打开游戏或打开面板时，再从 PlayerPrefs 读出来，对同一份 InputActionAsset **重新施加**这些覆盖。这样玩家改的键就会一直生效。

**二、用到的 Unity API（都在 UnityEngine.InputSystem 里）**

| 用途 | API | 说明 |
|------|-----|------|
| 显示当前键位 | `InputAction.GetBindingDisplayString(bindingIndex)` | 取某个 Binding 的「当前生效的键」的显示字符串（有 override 就显示 override，没有就显示默认）。 |
| 开始「等玩家按一个键」 | `InputAction.PerformInteractiveRebinding(bindingIndex)` | 返回一次**交互式重绑定**操作：游戏会等玩家按下任意键（或取消），按下的键会作为新绑定。可链式调用 `WithControlsExcluding("<Mouse>")` 排除鼠标、`WithCancelingThrough("<Keyboard>/escape")` 用 Esc 取消、`OnComplete` / `OnCancel` 回调。最后 `.Start()` 开始等待。 |
| 把新键写回 | 在 `OnComplete` 里，重绑定操作已经自动把玩家按下的键**写进该 Binding 的 Override**，无需再调一次 Apply；若你要手动写，可用 `InputAction.ApplyBindingOverride(bindingIndex, newPath)`。 | Override 会覆盖该 Binding 的默认 path，同一 Asset  everywhere 读到的都是新键。 |
| 持久化 | 我们自己实现：遍历所有 Action 的每个 Binding，若 `binding.overridePath` 非空，就记下 `(action.id, bindingIndex, overridePath)`，拼成字符串存 **PlayerPrefs**；加载时按 action.id 找到 Action，再 `ApplyBindingOverride(idx, path)` 写回去。 | Unity 没有把「整份 Asset 的 override」直接存 PlayerPrefs 的现成 API，所以用这种「自己序列化 override 列表」的方式。 |

**三、数据与资源关系（为何改键能全局生效）**

- **PlayerInputActions**（.inputactions）在项目里只有**一份**；场景里的 **GameplayInputEvents**、玩家身上的 **PlayerInput** / **PlayerInputHandler** 等，都是**引用这一份 Asset**（或同一份实例）。
- 我们对这份 Asset 里的某个 Action 做了 `ApplyBindingOverride` 之后，**所有**引用这份 Asset 的地方都会读到「该 Binding 的 overridePath」；所以玩家改的键会立刻在移动、技能、打开背包等逻辑里生效，**不需要**在每个用输入的地方再写一遍判断。

**四、流程分步（从打开面板到保存）**

1. **打开面板**  
   KeyConfigPanel 的 `Awake` 里：拿到 `InputActionAsset` 的 **Gameplay** ActionMap，先调 **LoadOverridesFromCurrentSave()**（从**当前存档**的 `keyConfigOverrides` 读覆盖列表，对每个 (actionId, bindingIndex, path) 调 `ApplyBindingOverride`），这样一打开看到的就已经是该存档保存的键位。**按键配置按当前存档独立保存**，在哪个存档调节的只对哪个存档有效。

2. **绑定行**  
   **BuildRows()**：按 **KeyList** 下子物体顺序（GetChild(0)～GetChild(15)）与 **RebindEntries** 一一对应；对第 i 个子物体取 **KeyConfigRow** 组件，再根据 RebindEntries[i] 找到对应的 InputAction 和 bindingIndex，调 **row.Set(显示名, action, bindingIndex, 重绑回调, 恢复默认回调)**，把显示名、当前键位和两个按钮逻辑绑好。**16 行需你在 KeyList 下手动创建**，顺序必须与「七、16 行顺序」一致。

3. **显示当前键位**  
   每一行用 `action.GetBindingDisplayString(bindingIndex)` 得到当前键的显示文本（有 override 显示 override，没有就显示 .inputactions 里的默认）。

4. **点击「重绑」**  
   用户点某一行的「重绑」→ 调 **OnRebindClickedWithRow(action, bindingIndex, row)**：  
   - 该行 **KeyText** 改为「按任意键...」，**重绑按钮**设为不可点（避免重复点击）。  
   - 把该 action **Disable**（避免重绑过程中触发游戏逻辑）。  
   - 调 `action.PerformInteractiveRebinding(bindingIndex).WithControlsExcluding("<Mouse>").WithCancelingThrough("<Keyboard>/escape")`，再挂 **OnComplete** / **OnCancel**，最后 **Start()**。  
   - 玩家按下键盘上某个键后，**OnComplete** 被调：新键已由 Input System 写进该 Binding 的 override；再 **SaveOverrides()** 写进 PlayerPrefs，**RefreshKeyText** 刷新所有行显示，恢复该行按钮可点。  
   - 若玩家按 **Esc**，走 **OnCancel**：不写 override、不保存，只恢复显示和按钮可点。

5. **保存格式**  
   **SaveOverrides()**：遍历 Gameplay/UI 下每个 Action 的每个 Binding，若 `binding.overridePath` 非空，就拼成 `"actionId,bindingIndex,overridePath"`，多条用分号 `;` 拼成一个大字符串，通过 **GameStateMachine.SetKeyConfigOverrides()** 写入**当前存档**并立即保存；无存档时不写入。  
   **LoadOverrides()**：从 PlayerPrefs 读出字符串，按 `;` 拆成多条，再按 `,` 拆成三段（第三段是 path，可能带逗号，所以用 `Split(new[] { ',' }, 3)` 只拆成 3 段）；用 actionId 在 Gameplay 里找到 InputAction，再 `ApplyBindingOverride(idx, path)`。

**五、小结**

- **方式**：Unity 新输入系统的 **Binding Override** + **PerformInteractiveRebinding**，不改 .inputactions 资源，只改运行时覆盖并持久化到 PlayerPrefs。  
- **生效范围**：所有使用同一份 PlayerInputActions 的代码（移动、技能、UI 快捷键等）都会自动用新键，无需额外对接。  
- **扩展**：若要增加「可配置项」，在 **RebindEntries** 里加一条 (action名, 复合子名或 null, 显示名)，并保证该 Action 在 Gameplay 里存在且有一个可覆盖的键盘 Binding 即可。

**六、每一行的 UI 元素有哪些？改键过程中各自有什么用？**

每一行（**KeyConfigRow**）对应「一个可配置的键位」，例如「技能1」「移动-上」。行内建议有下面**四个**元素（名字与脚本约定一致，若用预制体需按此命名）：

| 元素 | 建议命名 | 类型 | 在改键过程中的作用 |
|------|----------|------|--------------------|
| **动作名称** | **Label** | Text | 固定显示这一行是哪个操作（如「技能1」「移动-上」「背包」）。**不改键时**让玩家知道「当前要改的是啥」；**等待按键时**也能一眼看出是在为哪个动作设键。 |
| **当前键位** | **KeyText** | Text | 显示**当前生效的键**（有覆盖就显示覆盖键，没有就显示 .inputactions 里的默认键，如 "Q" "W" "Left Shift"）。**不改键时**让玩家看到现在用的是哪个键；**点完「重绑」并按下新键后**或**点「恢复默认」后**，脚本会刷新这里。 |
| **重绑按钮** | **Btn_Rebind** | Button | 玩家点它表示「我要改这一行的键」。点击后脚本会进入 **PerformInteractiveRebinding**；玩家在键盘上按下一个键后，新键写回 override、保存到 PlayerPrefs，并**刷新当前键位**显示；若按 Esc 则取消，不改变键位、不保存。 |
| **恢复默认按钮** | **Btn_Reset** | Button | 玩家点它表示「这一行改回 .inputactions 里的默认键」。点击后脚本对该 Binding 调 **RemoveBindingOverride**，清除覆盖，再 **SaveOverrides** 并**刷新当前键位**显示，KeyText 会变回默认键（如 Q、W、Space）。 |

**小结**：一行里「名称 + 当前键 + 重绑 + 恢复默认」四个元素；若用 **KeyConfigRow** 预制体，子物体命名为 **Label**、**KeyText**、**Btn_Rebind**、**Btn_Reset**，并在预制体根上挂 **KeyConfigRow** 脚本并把这四个引用拖好即可。

**七、行是手动创建的，共 16 行，顺序必须固定**

**行数和顺序**  
按键配置面板一共 **16 行**，**不在运行时生成**，而是**你在 KeyList 下手动创建 16 个物体**，每个物体挂 **KeyConfigRow**，子物体为 **Label**、**KeyText**、**Btn_Rebind**、**Btn_Reset**。  
脚本在 **Awake** 里会按 **KeyList 下子物体的顺序**（第 1 个、第 2 个……第 16 个）与 **RebindEntries** 数组一一对应：第 1 行对应技能1，第 2 行对应技能2，……，第 16 行对应移动-右。**顺序不能乱**，否则“技能1”会绑到错误的键位上。

**16 行顺序（必须与 KeyList 子物体顺序一致）**

| 顺序 | 显示名   | 顺序 | 显示名   |
|------|----------|------|----------|
| 1    | 技能1    | 9    | 技能树   |
| 2    | 技能2    | 10   | 菜单     |
| 3    | 技能3    | 11   | 闪避     |
| 4    | 技能4    | 12   | 跳跃     |
| 5    | 回血药剂 | 13   | 移动-上  |
| 6    | 回蓝药剂 | 14   | 移动-下  |
| 7    | 按键配置 | 15   | 移动-左  |
| 8    | 背包     | 16   | 移动-右  |

**代码在做什么**  
**Awake** 里先 **LoadOverrides()**（从 PlayerPrefs 恢复上次保存的键位），再 **BuildRows()**。**BuildRows()** 里：  
对 i = 0～15，取 `keyListRoot.GetChild(i)`，取其上的 **KeyConfigRow** 组件，再根据 **RebindEntries[i]** 找到对应的 InputAction 和 bindingIndex，调 **row.Set(显示名, action, bindingIndex, 重绑回调, 恢复默认回调)**。这样每一行的显示名、当前键位和重绑/恢复默认逻辑就绑好了。若某一行没有挂 KeyConfigRow 或 KeyList 下不足 16 个子物体，脚本会打 Warning 并跳过该行。

### 2.3 重绑功能 - 实现思路简述

点击某一行的「**重绑**」后流程如下：

1. **等待按键**：该行键位文字变为「按任意键...」，重绑按钮暂时不可点；Input System 开始等待一次键盘按键（鼠标按键被排除，按 **Esc** 可取消）。
2. **按下新键**：玩家按下目标键后，新键会写入该动作的 Binding Override，并自动 **SaveOverrides()** 存到 PlayerPrefs，所有行的键位文字刷新，按钮恢复可点。
3. **按 Esc 取消**：不修改键位、不保存，只恢复显示和按钮。

「**恢复默认**」：清除该 Binding 的 Override，保存并刷新显示。

**编辑器里怎么做（重绑能用的前提）**

1. **KeyConfigPanel 根物体**  
   - 挂 **Key Config Panel** 脚本；**Input Action Asset** 拖成 **PlayerInputActions**，**Key List Root** 拖成 **KeyList**（Scroll View 下的 Content，即 KeyList）。

2. **KeyList 下 16 行**  
   - 每行一个子物体，**顺序**与脚本里 RebindEntries 一致：技能1、技能2、技能3、技能4、回血药剂、回蓝药剂、按键配置、背包、技能树、菜单、闪避、跳跃、移动-上、移动-下、移动-左、移动-右。  
   - **每一行**（如「技能1」）：  
     - 挂 **Key Config Row** 组件；  
     - 子物体：**Label**（Text）、**KeyText**（Text）、**Btn_Rebind**（Button，文字「重绑」）、**Btn_Reset**（Button，文字「恢复默认」）；  
     - 在 **Key Config Row** 的 Inspector 里把 **Label**、**Key Text**、**Rebind Button**、**Reset Button** 四个槽分别拖成上面四个子物体。  
   - 若某行未挂 KeyConfigRow 或四个槽未拖全，该行不会参与重绑，Console 会有警告。

3. **保存**  
   - 改完预制体或场景后 **Ctrl+S** 保存；运行后改键会存到 PlayerPrefs，下次打开面板会 **LoadOverrides** 自动应用。

### 2.4 测试

- 运行关卡，按 **X**，按键配置面板应出现在 **Mid** 层，中间为可滚动的 **16 行**（技能1～4、回血/回蓝药剂、按键配置/背包/技能树/菜单、闪避、跳跃、移动-上/下/左/右），每行显示当前键位，可点「重绑」改键（会显示「按任意键...」）、点「恢复默认」恢复，点「关闭」或再按 X 关闭面板。

### 2.5 若按 Esc / X / C / V 无反应

按键盘没有弹出菜单、按键配置、背包或技能树时，按下面逐项检查：

1. **场景里是否有「桥接」组件（Esc/X/C/V 靠它才弹面板）**
   - 按 Esc/X/C/V 弹面板**不靠 PlayerInput**，而靠 **GameplayInputEvents** 和 **GameplayUIInputBridge**。打开关卡场景，在 **Hierarchy** 里选中**玩家**（或任意一个物体），看 **Inspector** 是否同时有 **Gameplay Input Events** 和 **Gameplay UI Input Bridge**。没有则按本文「步骤 0」第 3 步：在玩家（或新建 GameplayInput 空物体）上添加这两个组件，并把 **PlayerInputActions** 拖到 Gameplay Input Events 的 **Input Action Asset**。
2. **Input Action Asset 是否已拖入**
   - 选中该物体，在 **Inspector** 里看 **Gameplay Input Events** 组件的 **Input Action Asset** 是否已拖入 **PlayerInputActions**（在 Assets/Input/ 下）。若为空，从 Project 把 **PlayerInputActions** 拖进去，保存场景。未分配时运行游戏会在 **Console** 里看到黄色警告：`[GameplayInputEvents] Input Action Asset 未分配……`。
3. **项目是否使用新输入系统**
   - **Edit → Project Settings → Player**，展开 **Other Settings**，找到 **Active Input Handling**。必须为 **Input System Package (New)** 或 **Both**，不能是 **Input Manager (Old)**。若你改了该项，需**重启 Unity** 后生效。
4. **PlayerInputActions 里是否有对应 Action**
   - 在 Project 里双击 **Assets/Input/PlayerInputActions** 打开，确认 **Gameplay** 或 **UI** 地图下有 **ToggleMenu**（Esc）、**ToggleKeyConfig**（X）、**ToggleBackpack**（C）、**ToggleSkillTree**（V）四个 Action，且各自绑定了按键。代码会先查 Gameplay、再查 UI，两个地图任一即可。
5. **EventSystem 重复（"There can be only one active Event System"）**
   - UIManager 在首次使用时若场景里**已有** EventSystem，会复用该物体并 DontDestroyOnLoad，**不会**再加载一份；若仍报两个 EventSystem，请检查关卡场景中是否放了多个 EventSystem，只保留一个即可。

### 2.6 光标与 Z 键

- **Esc 不再控制光标**：仅负责打开/关闭菜单面板，不再用于显示或隐藏鼠标。
- **打开任意面板**（菜单/按键配置/背包/技能树）：光标会**自动显示**并解锁。
- **关闭面板后**：光标**不会自动隐藏**；只有在**点击场景中的非 UI 区域**（如地面、角色）时才会隐藏并锁定。
- **Z 键**：若你在编辑器里添加了 **ToggleCursor**（Button，绑定 Z），**Cursor Visibility Controller** 会监听并切换光标。同一物体上需挂 **Cursor Visibility Controller**（见步骤 0 第 3 步）。

### 2.7 配置检查（仍无效时逐项核对）

1. **只在一处挂**：**Gameplay Input Events** 和 **Gameplay UI Input Bridge** 只应挂在**一个**物体上（推荐**玩家**），并在该物体上把 **Input Action Asset** 拖成 **PlayerInputActions**。若玩家和 GameplayInput 两个物体都挂了，请**删掉其中一处**（建议删掉 GameplayInput 上的，只保留玩家身上的），否则 FindObjectOfType 可能找到未拖 Asset 的实例，面板与禁用 Gameplay 会失效。
2. **同一份 PlayerInputActions**：**玩家**身上的 **Player Input** 的 **Actions** 与 **GameplayInputEvents** 的 **Input Action Asset** 必须拖**同一份** **PlayerInputActions**，否则禁用 Gameplay 时角色仍会响应移动/攻击。
3. **关闭按钮点不了**：EventSystem 上建议挂 **Input System UI Input Module**（Add Component → 搜 **Input System UI Input Module**）；关闭按钮的 **GameObject 名**必须为 **Btn_Close**。
4. **Input 配置**：Gameplay 里 **UseHealthPotion** / **UseManaPotion**（Button，T/Y）；UI 里 **ToggleMenu** / **ToggleKeyConfig** / **ToggleBackpack** / **ToggleSkillTree**（Button）即可。

## 三、小结（对齐需求说明书）

| 面板           | 预制体名        | 放置路径              | 脚本组件        | 打开按键 | 层级 |
|----------------|-----------------|-----------------------|-----------------|----------|------|
| 菜单面板       | MenuPanel       | Resources/UI/MenuPanel       | MenuPanel       | Esc      | Top  |
| 关卡内声音设置 | LevelSoundPanel | Resources/UI/LevelSoundPanel | LevelSoundPanel | 菜单内 Btn_Settings | Top  |
| 按键配置面板   | KeyConfigPanel  | Resources/UI/KeyConfigPanel | KeyConfigPanel  | X        | Mid  |

**菜单面板（需求十九）**

- **继续游戏**：Btn_Resume（或 Btn_Close）→ 关闭菜单并恢复。
- **退出游戏**：Btn_Quit → **保存并返回主菜单**（非退出应用）。
- **声音设置**：Btn_Settings → 打开 **LevelSoundPanel**（仅关卡内 BGM 滑块，按当前存档保存）。
- **战斗回忆**：Btn_BattleMemory → 仅**通关后**显示，打开战斗回忆面板（选择要重新挑战的 Boss）。

**按键配置面板（需求十三、十九）**

- 共 **16 行**，需在 **KeyList** 下**手动创建**，顺序与脚本 **RebindEntries** 一致（见「七、16 行顺序」）。每行挂 **KeyConfigRow**，子物体 **Label**、**KeyText**、**Btn_Rebind**、**Btn_Reset**；用于为技能、药剂、面板键、闪避、跳跃、移动等配置按键。**按键配置按当前存档独立保存**，重绑或恢复默认后写入当前存档并立即保存；关卡加载时从当前存档应用键位。

按以上步骤配置后，按 Esc 打开菜单、按 X 打开按键配置，由 **GameplayUIInputBridge** 统一驱动。
