# 数据配置文件合并方案

> 将「同类型、多份」的配置收拢为**一个 ScriptableObject + 列表**，用列表项（或索引/枚举）区分，减少 asset 数量、便于维护。

---

## 一、当前配置与合并建议总览

| 类型 | 当前 asset 数量 | 区分维度 | 建议 | 合并后 |
|------|-----------------|----------|------|--------|
| **敌人基础属性** | 5 份（MeleeMinion / RangedMinion / Elite / Guardian / Boss） | `EnemyType` 枚举 | 合并为 **EnemyStatsDatabase**，列表按类型 | **1 个** |
| **关卡配置** | 1～5 份（LevelConfig_1 … _5） | 关卡编号 1～5 | 合并为 **LevelConfigDatabase**，列表按 levelIndex | **1 个** |
| **掉落表** | 1～5 份（DropTable_Level1 … _5） | 关卡编号 1～5 | 合并为 **DropTableDatabase**，列表按 levelIndex | **1 个** |
| **武器** | 2 份（Sword / Gun） | `WeaponType` 枚举 | 合并为 **WeaponDatabase**，列表按类型（可存引用或内联数据） | **1 个**（+ 可选保留原 SO 作引用） |
| 玩家成长 | 1 份 | 全局唯一 | 不合并 | 1 个 |
| 难度系数 | 1 份 | 全局唯一 | 不合并 | 1 个 |
| 玩家移动 | 1 份 | 全局唯一 | 不合并 | 1 个 |

---

## 二、各合并项设计

### 2.1 敌人基础属性 → EnemyStatsDatabase

- **现状**：5 个 `EnemyStatsSO`（EnemyStats_MeleeMinion / RangedMinion / Elite / Guardian / Boss），每个敌人预制体拖一份 SO。
- **合并后**：
  - 一个 **EnemyStatsDatabaseSO**，内含 `List<EnemyStatsEntry>`，每项对应一种 `EnemyType`。
  - 提供 `EnemyRuntimeStats GetScaled(EnemyType type, int difficulty, DifficultyScalingSO scaling)`。
- **引用方式**：场景/预制体上只拖 **EnemyStatsDatabase** + 选择 **EnemyType**（枚举），不再拖 5 个 SO。
- **效果**：5 个 asset → 1 个；新增敌人类型只需在列表里加一条。

---

### 2.2 关卡配置 → LevelConfigDatabase

- **现状**：每关一个 `LevelConfigSO`（LevelConfig_1 … LevelConfig_5），LevelBootstrapper / LevelDirector 拖「本关」那一份。
- **合并后**：
  - 一个 **LevelConfigDatabaseSO**，内含 `List<LevelConfigData>`（或按 levelIndex 索引），每项对应关卡 1～5。
  - 提供 `LevelConfigData GetConfigForLevel(int levelIndex)`（或返回与现有 API 兼容的接口）。
- **引用方式**：LevelBootstrapper / LevelDirector 只拖 **LevelConfigDatabase**，运行时用 `CurrentRun.levelIndex` 取当前关配置。
- **效果**：多份 LevelConfig → 1 个；扩展关卡时只在列表里加一项。

---

### 2.3 掉落表 → DropTableDatabase

- **现状**：每关一个 `DropTableSO`（DropTable_Level1 … _5），精英/宝箱/商店拖「本关」掉落表。
- **合并后**：
  - 一个 **DropTableDatabaseSO**，内含按关卡分的掉落列表（如 `List<DropTableByLevel>`，每项 levelIndex + entries）。
  - 提供 `string Roll(int levelIndex, Random rng)` 或返回「可 Roll 的句柄」。
- **引用方式**：EnemyController / 宝箱 / 商店只拖 **DropTableDatabase**，运行时用 `CurrentRun.levelIndex` 取本关掉落并 Roll。
- **效果**：多份 DropTable → 1 个；改权重只改一张表。

---

### 2.4 武器 → WeaponDatabase（内联，可删 Sword/Gun.asset）

- **现状**：每种武器一个 `WeaponSO`（Sword、Gun），掉落/商店时拖一个「武器源」。
- **合并后**：
  - 一个 **WeaponDatabaseSO**，内含 `List<WeaponEntryData>`（数据内联，与 WeaponSO 字段一致），按 `WeaponType` 区分。
  - 提供 `Roll(WeaponType, rarity, rng)`、`RollRandomWeapon(rarity, rng)`（需求：剑/枪各半）。
- **引用方式**：只拖 **WeaponDatabase**；掉落时从 Database 随机类型再 Roll。
- **效果**：2 个 asset → 1 个；**可删除原 Sword.asset、Gun.asset**，挂载处改拖 WeaponDatabase 即可。

---

## 三、不合并的配置（保持单例）

- **LevelGrowthSO**：玩家 1～10 级成长，全局一份。
- **DifficultyScalingSO**：难度系数，全局一份。
- **PlayerMovementConfigSO**：移动参数，全局一份。

这些本身就只有一份，用「列表区分」没有意义，保持一个 asset 即可。

---

## 四、合并清单（哪些删掉、合并成哪个、默认文件名）

| 合并后的 1 个 asset（默认文件名） | 被合并掉的旧 asset（迁移后可删） |
|----------------------------------|----------------------------------|
| **EnemyStatsDatabase.asset**     | EnemyStats_MeleeMinion、EnemyStats_RangedMinion、EnemyStats_Elite、EnemyStats_Guardian、EnemyStats_Boss（共 5 个） |
| **LevelConfigDatabase.asset**    | LevelConfig_1、LevelConfig_2 … LevelConfig_5（1～5 关各 1 份） |
| **DropTableDatabase.asset**      | DropTable_Level1 … DropTable_Level5（1～5 关各 1 份） |
| **WeaponDatabase.asset**         | Sword、Gun（共 2 个；数据已内联到 Database，可放心删） |

**不合并、保留原样**：DifficultyScalingConfig、LevelGrowthConfig、PlayerMovementConfig、PlayerAnimator（动画控制器）等仍各 1 份，不删不改。

## 五、默认数据（需求书已定数值）

- 若项目里**没有**对应的现有 SO，菜单「从现有 xxx 创建 xxx Database」会**按《功能需求说明书》§十八（已定数据）**直接写入默认数据，无需手填。  
- **敌人**：难度=1 基础值（近战 60/10/5/3.8、远程 45/12/3/3.6、精英 160/18/8/4、守卫 260/22/10/4.2、Boss 750/28/12/4.5）及小怪 10 金 10 经验、精英 30 金 30 经验、守卫/Boss 0 金 0 经验。  
- **关卡**：5 关守卫者 3/4/6/7/10，每格精英上限 3、商店固定 2、怪物/宝箱范围等。  
- **掉落**：第 1～5 关权重（普通/精良/史诗/传说武器、回血回蓝、仙露）按需求 §十八（七）。  
- **武器**：若有现有 Sword/Gun.asset 则复制进 Database；若无则生成剑/枪两条默认品质范围。

## 六、配置免挂载：ConfigManager 单例 + Resources

- 所有数据配置**不再在场景或预制体上挂载**。  
- **ConfigManager**（`Game.ConfigManager`）继承项目中的 **BaseManager** 单例，运行时从 **Resources/配置/** 按需加载各 ScriptableObject。  
- 代码中通过 **ConfigManager.GetInstance().GetXxx()** 获取，例如：  
  - `GetEnemyStatsDatabase()`、`GetLevelConfigDatabase()`、`GetDropTableDatabase()`、`GetWeaponDatabase()`  
  - `GetLevelGrowth()`、`GetDifficultyScaling()`、`GetPlayerMovement()`

因此只需保证 **Resources/配置/** 下存在对应名称的 asset（见下节），无需在 Inspector 中拖任何配置。

---

## 七、编辑器里具体操作步骤

### 7.1 菜单与刷新

- 顶部菜单为 **游戏**（中文）。  
- 若没有出现「游戏」菜单：点 **Assets → Refresh**（或 **Ctrl+R**），等编译结束；若有编译错误需先修复。

### 7.2 生成全部配置（中文命名，放入 Resources/配置/）

1. 打开 Unity，打开本工程。  
2. 点击 **游戏** → **合并配置** → **一键创建全部配置（需求书默认数据）**。  
3. 会在 **Assets/Resources/配置/** 下创建（无该文件夹会自动创建）：  
   - **敌人属性库.asset**、**关卡配置库.asset**、**掉落表库.asset**、**武器库.asset**  
   - **玩家成长库.asset**、**难度系数.asset**、**玩家移动.asset**（后两者若已存在则跳过）  
4. 以上 asset 名称与 ConfigManager 的 Resources 路径一致，运行时自动加载，**无需在任何场景或预制体上挂载**。

### 7.3 场景与预制体（无需拖配置）

1. **敌人（EnemyController）**  
   - 只需在 Inspector 中选 **Enemy Type**（近战小怪 / 远程小怪 / 精英 / 守卫者 / Boss）。  
   - 敌人属性库、难度系数、掉落表库、武器库均由 ConfigManager 提供。

2. **关卡（LevelBootstrapper、LevelDirector）**  
   - 无需拖任何配置；关卡配置库由 ConfigManager 提供。

3. **主菜单、玩家**  
   - 玩家成长、玩家移动等均由 ConfigManager 提供，无需挂载。

### 7.4 若提示缺少配置

- 若运行时报错缺少「玩家成长」等：请执行一次 **游戏 → 合并配置 → 一键创建全部配置**，确保 **Resources/配置/** 下存在对应中文命名的 .asset。

---

## 七、实现与迁移注意

1. **兼容**：若需平滑迁移，可在一段时间内同时支持「旧：拖单份 SO」与「新：拖 Database + 枚举/关卡号」，再逐步移除旧引用。
2. **预制体/场景**：合并后需在 Inspector 中把原 SO 引用改为 Database + 类型/关卡选择；旧 asset 可在迁移后删除。
3. **查找方式**：Database 内列表用 **枚举或 levelIndex** 查找；武器为内联数据，无需再保留 Sword/Gun.asset。

以上方案使「同类型不同变体」的配置都收拢到**一个数据配置文件 + 列表**，默认文件名与需求书默认数据已内置，编辑器操作见第六节。
