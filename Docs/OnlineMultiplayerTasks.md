# 联机与后端改造任务清单

## 当前命名边界
- 账号登录、注册、会话保持属于账号/平台能力，后续使用 `Account` 或 `Platform` 命名。
- 好友、聊天、好友申请、援助请求通知属于社交能力，可以继续使用 `Social` 命名。
- 实时副本战斗属于联机副本能力，后续使用 `Dungeon` 或 `OnlineDungeon` 命名。
- 当前 `Backend/SocialBackend` 实际承担平台后端职责，后续建议改名为 `GameBackend` 或 `PlatformServer`。

## 联机副本方向
- 新增独立的联机副本服务器进程，负责实时战斗、玩家同步、怪物 AI、掉落、暂停、胜负结算。
- 当前 `OnlineDungeonServer` 先承担副本实例会话管理，实时战斗同步将在后续接入 Unity/Netcode 服务器运行时。
- 平台后端只负责账号、好友、聊天、存档、援助请求、创建副本会话和最终结算保存。
- 玩家体验上平等，底层由副本服务器统一裁判战斗结果。
- 援助功能改造为“加入同一个副本实例”，不再区分主玩家和援助方的网络地位。

## 网络玩家改造
- 停止使用手动克隆远端玩家残影作为长期方案。
- 创建真正的网络玩家预制体，由副本服务器生成和销毁。
- 本地玩家启用输入、相机和 HUD，远端玩家只显示模型、动画、武器和状态。
- 玩家面板打开请求由服务器广播，确保所有客户端同步暂停和同步打开同类型面板。

## 战斗权威改造
- 怪物生成、AI、受击、死亡和掉落由副本服务器统一决定。
- 客户端只发送移动、攻击、技能、拾取等输入或请求。
- 经验、物品、成长等结果由服务器结算后写回平台后端。
- 掉线、死亡、主动退出、通关失败和通关胜利都要走统一的副本结算流程。
- 待完成：把联机副本奖励配置生成流程工具化，避免以后手动维护 `dungeon-rewards.json` 与 Unity 配置不一致。

## 后续扩展
- 支持 2 人援助后，再扩展为 2-4 人组队副本。
- 支持多个副本服务器实例，由平台后端分配房间地址和端口。
- 数据库从本机 SQLite 逐步迁移到 PostgreSQL 或 MySQL。
