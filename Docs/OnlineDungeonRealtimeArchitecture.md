# 联机副本最终实时架构

## 目标架构

联机副本最终采用服务器权威状态同步，不采用帧同步。

长期数据继续由平台后端负责，包括账号、好友、聊天、玩家资料、头像、存档和社交援助邀请。副本战斗由联机副本服务器负责，包括玩家加入、副本参与者验证、敌人权威状态、掉落、拾取、经验金币、玩家死亡、Boss 阶段和胜负结算。

## 网络传输

- HTTP/TCP：账号、好友、聊天、存档、副本创建和加入前流程。
- UDP 实时通道：联机副本内的高频战斗同步。
- 不可靠状态通道：玩家输入、位置、朝向、瞄准方向、动画参数、敌人快照。
- 可靠事件通道：技能释放意图、拾取请求、死亡、进入 Boss、面板开关、结算。

当前第一阶段只建立 UDP 实时入口和协议边界，现有 HTTP 同步暂时保留，用于保证当前联机功能仍可测试。

## 同步方式

客户端向服务器提交输入和意图，服务器维护权威副本状态并广播快照。客户端本地玩家使用预测保证手感，远端玩家、敌人和掉落物使用快照插值显示。

服务器权威内容：

- 敌人 AI 和敌人血量。
- 伤害结算。
- 掉落生成和拾取确认。
- 经验、金币和成长结算。
- 玩家死亡、退出、副本胜负和 Boss 阶段推进。

客户端表现内容：

- 本地输入采样。
- 摄像机、UI、音效。
- 动画和特效表现。
- 远端角色快照插值。

## 迁移阶段

1. 实时协议骨架：副本服务器开放 UDP 端口，完成 hello/helloAck 和参与者验证。
2. Unity 实时客户端：加入 UDP transport，连接副本实时端口，但不替换现有 HTTP 同步。
3. 玩家输入上行：客户端上传输入、瞄准方向、动作意图；服务器记录参与者实时状态。
4. 权威快照下行：服务器广播玩家和敌人快照；客户端使用快照插值替换 HTTP 姿态轮询。
5. 可靠事件通道：迁移技能释放、拾取、死亡、Boss、面板开关等事件。
6. 服务器权威战斗：敌人 AI、伤害、掉落和奖励由服务器统一推进。
7. 清理 HTTP 战斗轮询：保留 HTTP 作为平台/调试接口，实时战斗走 UDP。
